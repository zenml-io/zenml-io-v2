LangGraph is a real graph-native agent runtime, with its own checkpointer for resuming a run and stepping back through it. Deep Agents and LangChain's `create_agent` sit on top of it. LangSmith Deployment packages all of that with sandboxes, an auth proxy, tracing, and hosted infra. Adopt the platform and you get a lot for free.

Kitaru is a different layer. It's a **replay-based eval layer** that sits beside whatever harness you picked: [`kitaru-langgraph`](https://docs.zenml.io/kitaru/adapters/langgraph) wraps your compiled graph, or your `create_agent` or Deep Agents build, and every `invoke()` lands as a session, with model calls, tool calls, and graph callbacks recorded as nodes you can replay and evaluate. It's framework-agnostic on purpose. The same eval loop works whether the team next to you is on LangGraph, Pydantic AI, the OpenAI Agents SDK, the Claude Agent SDK, Mastra, or the Vercel AI SDK. Running that same graph durably in production is ZenML's job; Kitaru replays and improves it. See [ZenML vs LangGraph & Deep Agents](/compare/zenml-vs-langgraph-deep-agents).

  LangGraph&rsquo;s checkpointer, resume, and time-travel are powerful inside the graph model. Your agent is a graph of nodes and edges, and LangGraph persists its state between supersteps.

  Kitaru doesn&rsquo;t ask you to touch the graph. Install it with `uv add kitaru-langgraph`. `KitaruGraphRunner` wraps the compiled graph you already built: no recompile, no swapped checkpointer, no different result. `invoke()` and `ainvoke()` come back exactly as LangGraph returns them. The session is what&rsquo;s new.

<FeatureWithGraphic title="One adapter, three ways in" reverse={true}>
  <CodePane
    slot="graphic"
    code={`# Direct compiled graph
runner = KitaruGraphRunner(builder.compile(), agent_id=AGENT_ID)

# LangChain's create_agent, also a LangGraph runnable
from langchain.agents import create_agent
runner = KitaruGraphRunner.from_agent_factory(
    create_agent,
    factory_kwargs={"model": "openai:gpt-5.4-mini", "tools": [lookup_order]},
    agent_id=AGENT_ID,
)

# Deep Agents: same adapter, the [deepagents] extra
from deepagents import create_deep_agent
runner = KitaruGraphRunner.from_agent_factory(
    create_deep_agent, factory_kwargs={...}, agent_id=AGENT_ID,
)`}
  />

  LangChain&rsquo;s `create_agent` and Deep Agents both return LangGraph runnables under the hood, so the same `kitaru-langgraph` adapter covers all three construction paths. Deep Agents needs the `kitaru-langgraph[deepagents]` extra.

  What changes is how much of the graph you can replay. A direct wrapper records the call and can replace the whole input. The two factory paths install middleware that also lets a replay override the model, prompt, system prompt, or model parameters, with exactly one live model call and never a cached response, and substitute matching `static` or `history` tool results. Wrap a subagent opaquely and it still shows up in the outer session; it just doesn&rsquo;t get its own substitution. `runner.capabilities` tells you which set you got.
</FeatureWithGraphic>

<FeatureWithGraphic title="Self-hosted eval server vs packaged platform">
  <SelfHostVsPackaged slot="graphic" />

  LangSmith Deployment packages runtime, sandboxes, auth proxy, and tracing into one managed product. If you want to offload the platform layer, that&rsquo;s a real offer.

  Kitaru ships the eval layer as a primitive you self-host: one FastAPI + Postgres server, with workers that replay and evaluate inside your own environment. It sits beside your observability rather than replacing it: Langfuse, LangSmith, Braintrust, Logfire, and Arize Phoenix stay your system of record, and Kitaru is where you re-run what they recorded.

  If your security team needs to know exactly where prompts, outputs, and traces live, &ldquo;in our own systems&rdquo; is a shorter conversation than a data-residency addendum on a hosted control plane.
</FeatureWithGraphic>

<FeatureWithGraphic title="Two different jobs: resume a graph vs replay a session" reverse={true}>
  <SandboxSecurity slot="graphic" />

  There&rsquo;s real infrastructure on the LangGraph side for its job: the checkpointer persists state between supersteps, so an interrupted or crashed graph resumes, and you can step back through recorded graph state. That lives inside the graph model, and it&rsquo;s good at it.

  Kitaru solves a different problem. `KitaruGraphRunner` wraps the compiled graph without recompiling it or replacing its checkpointer, and records one session per `invoke()` alongside whatever LangGraph is already doing. Hit an interrupt and it comes back unchanged, recorded on the session. Resume the thread with your own checkpointer and `Command(resume=...)`, and that resume call becomes a second session. Workers don&rsquo;t resume interrupts: a replay that hits one fails explicitly instead of pretending to finish.

  Two different jobs, not competing answers: LangGraph resumes a crashed graph. Kitaru replays a session to test a change.
</FeatureWithGraphic>

<FeatureWithGraphic title="Compare runs, don't manage deployments">
  <VersionedDeployments slot="graphic" />

  Both have a real story here. They answer different questions.

  LangSmith Deployment exposes agent endpoints (MCP, A2A, Agent Protocol, HITL, memory APIs) as part of its packaged runtime.

  Kitaru isn&rsquo;t a deployment platform. An experiment holds the change: override, tool policy, evaluators. An experiment run applies it to one cohort version and one agent version, fans out one replay per session, and evaluates baseline and replay alike. Drive it from the `kitaru` CLI, the Python client, the TypeScript SDK, or your coding agent through the `kitaru-mcp` server.
</FeatureWithGraphic>

## How the two surfaces map

| Concept | LangGraph / Deep Agents | Kitaru |
|---|---|---|
| Layer | Graph-native agent harness + runtime | Replay-based evals (how you test what it did) |
| Core unit | A node, persisted by the checkpointer between supersteps | A session: recorded model, tool, and graph callbacks, replayable |
| Composition | Compiled graph, or `create_agent` / `create_deep_agent` | Same graph wrapped once by `KitaruGraphRunner` |
| Resume after a crash | Checkpointer + `Command(resume=...)` on your own thread | Not the job. Kitaru replays a session; it doesn't resume a crashed graph |
| Replay depth | Not a concept | Direct wrapper: whole-input only. `create_agent` / Deep Agents: model, prompt, and tool-result overrides too |
| "Did my change help?" | Read the traces, compare by eye | Two runs over the same cohort, evaluated on both sides |
| Deployment / hosting | LangSmith Deployment (packaged runtime + auth proxy + tracing) | Self-hosted server; workers replay in your environment |
